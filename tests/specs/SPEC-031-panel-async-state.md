# SPEC-031：面板异步状态语义（三轴 + 一份词表）

## 背景

论文 / 数据 / 笔记三个面板各自手写「载入中…」「读取失败：xxx」「（暂无）」，
同一件事在不同面板说法不一样，也分不清几种本质不同的处境：

- 「原文件丢了」和「读取失败」不是一回事——前者重试没有用，得重新导入；
- 「首次加载失败」和「刷新失败」也不一样——后者要**留住上一次的结果**，
  并说明那不是最新结果；
- 「加载中」不能显示成「暂无数据」——数据还没到，不等于没有数据。

Pero 的设计契约（`DESIGN.md`「数据与异步状态」一节）说：分别表达
**有哪些数据**、**请求正在做什么**、**业务结果是什么**，并且明确
「请求成功不代表科学验证通过」。PurrCat 已经有 `acceptance` / `verification`
这套认识论词表，所以本 spec 的状态层**只说界面处于什么状态，不给结论盖章**。

## 行为

1. **状态是三件正交的事，不是��张扁平枚举。**
   - `data`：屏幕上现在有什么 —— none / partial / stale / complete
   - `request`：请求在做什么 —— idle / first_load / refresh / submitting / cancelling / cancelled / completed
   - `result`：业务结果是什么 —— pending / ok / empty / failed / unavailable
2. **三轴组合出最终状态**，规则表按顺序命中第一条。
3. **词表只有一份**，写在 `ui/web-minimal/assets/async-state.js` 里：
   Python 从那段 JSON 读，浏览器加载同一个文件。契约测试穷举全部组合，
   断言两边推出同一个状态。
4. **服务端只说业务结果**（`result` / `reason` / `action`），
   **客户端补自己知道的那两轴**（屏幕上有没有内容、请求在做什么）。
5. **失败时错误体多带一个 `status`**，面板据此分清「不可用」和「失败」，
   也知道该给「重试」还是「导入」。
6. **刷新失败保留上一次的内容**，并说明那不是最新结果；
   **换对象时必须清掉旧内容**，不能把旧对象的数据冒充成新对象的。
7. **空态按原因给不同的下一步**：「从没有过」给导入，「筛掉了」给调整筛选，
   「还没跑完」给开始任务。
8. **骨架屏只画灰色块**，不伪造数值。
9. **状态层不给结论盖「已验证」的章**：状态字典里没有 acceptance / verification。

## 验收标准

- [ ] AC-1：三轴词表封闭，取值之外一律拒收。
- [ ] AC-2：首次加载显示骨架屏，不显示「暂无数据」。
- [ ] AC-3：刷新失败保留旧内容 + 提示 + 重试；首次加载失败显示整块错误。
- [ ] AC-4：「原文件丢失 / 变了」判为不可用，给「导入」而不是「重试」。
- [ ] AC-5：空态按原因给不同入口。
- [ ] AC-6：换对象时清掉旧内容。
- [ ] AC-7：Python 与 JS 读同一份词表，推出同一个状态。
- [ ] AC-8：状态字典不含 acceptance / verification。
- [ ] AC-9：接口错误体带 `status`；正常响应形状不变。

## 非目标

- 不做全局加载指示器；状态只作用于受影响的最小区域。
- 不给 Agent 工具加状态字段（工具返回的是文字，不是界面状态）。
- 不改 Agent 主循环、工具批次与 Hook 阶段顺序。
- 不动其他面板（会话 / 设置 / 市场等）的既有呈现。

## 风险与回滚

- 规则表改动会同时影响前端与后端推导；L3 契约测试穷举全部组合，改错会立刻红。
- 接口错误体多一个 `status` 字段是纯增量，不影响既有字段与状态码。
- 回滚：删掉 `src/utils/async_state.py`、`src/utils/panel_state.py`、
  `src/server/api/research_status.py` 与两个前端资产，三个面板退回各自手写文案。
