# SPEC-028：图表（带出处的图表规格）

## 背景

SPEC-027 有了数据集与查询收据，但「把数据画出来」还差一步。缺的不是渲染，是**出处**：
一张柱状图如果说不清「这些柱子来自哪个文件的哪一版、每根柱子由原文件第几行算出来、
跳过了几组、丢了几个值」，它就只是一张图，学生没法判断能不能信。

现有能力里没有可复用的：PurrCat 没有图表库，也没有「图 → 数据」的往返。

本 spec 引入**图表规格**：后端生成一份带完整出处的 JSON 规格，前端照着渲染。
规格本身内容寻址、可被引用，就像查询收据一样。

## 行为

1. **图表是规格，不是图片**。后端返回 JSON，前端用 SVG 渲染（PurrCat 不引入图表库）。
2. **四种图型**：`bar` / `line` / `area` 按类目聚合，`scatter` 逐行画点。
   金融专用的蜡烛图、桑基图与科研场景无关，不做。
3. **口径随图走**：每份规格记录用的类目列、数值列、聚合方式、单位声明、粒度、分母，
   以及被显式解释为数字的列。
4. **出处随图走**：数据集 id、版本 id 与标签、SHA-256、解析器版本、完整的质量报告，
   以及每个数据点来自原文件第几行。
5. **数值必须是有限数**：缺值与非数值不画，并计入 `excludedValues`——不给读者一根假的柱子。
6. **标签列与数值列必须不同**：相同则拒收，否则图上分不清横轴是什么。
7. **数值运算要求已解释**：未解释的文本列不能求和或参与数值比较，拒收并提示先解释。
8. **重复坐标点拒收**：散点图里重复的点会互相盖住，让用户先决定是聚合还是换轴。
9. **最多 50 组**：超出的组计入 `omittedGroups` 并写进说明，不静默截断。
10. **内容寻址**：规格按自身字节的哈希命名与校验，被改动过的规格拒绝读取。
11. **方法只是声明**：每份规格都带一句「方法是声明，不是科学检查」，界面要显示出来。

## 工具与接口

| 入口 | 作用 |
| --- | --- |
| `Data` 的 `chart` 动作 | 画一张图并保存规格 |
| `Data` 的 `charts` 动作 | 列出已保存的规格 |
| `POST /api/data/datasets/{id}/chart` | 面板画图 |
| `GET /api/data/charts` | 列出规格 |
| `GET /api/data/charts/{digest}` | 读规格 |

## 验收标准

- [ ] AC-1：柱状图按类目聚合，数值与源数据一致。
- [ ] AC-2：计数聚合不需要把列解释成数字；求和与数值比较需要。
- [ ] AC-3：标签列与数值列相同则拒收。
- [ ] AC-4：缺值与非数值不画，并计入 `excludedValues`。
- [ ] AC-5：散点图需要两个已解释的数值列；重复坐标点拒收。
- [ ] AC-6：最多 50 组，超出的记入 `omittedGroups`。
- [ ] AC-7：规格带数据集 id、版本、SHA-256、解析器版本、质量报告与逐行出处。
- [ ] AC-8：规格内容寻址，被改动后拒绝读取；同样的口径得到同样的 id。
- [ ] AC-9：规格与界面都写明「方法是声明，不是科学检查」。
- [ ] AC-10：面板能选图型、横纵轴与聚合方式，画出图并显示出处。

## 非目标

- 不做图片导出与位图渲染。
- 不做饼图、雷达图、蜡烛图、桑基图。
- 不做多数据集合并画图——一张图只对一个数据集的一个版本。
- 不做统计推断与置信区间。画的是描述统计，不是结论。
- 不改 Agent 主循环、工具批次与 Hook 阶段顺序。

## 风险与回滚

- 「方法是声明」这句话必须留在图上。少了它，一张图很容易被当成结论。
- SVG 渲染是手写的，坐标轴刻度与标签在极端数据下可能挤（类目很多时标签会隔几个显示一个）。
  超长类目名会被截断到 10 个字符。
- 回滚：`src/data/chart.py` 与面板图表区都是新增，删除即回到现状；已保存的规格留在磁盘上不影响既有功能。
