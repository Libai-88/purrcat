# SPEC-029：论文 ↔ 数据证据链合一

## 背景

到 SPEC-027 为止，PurrCat 有两条各自完整的证据链：

- **论文链**：研究记录 → 结论 → 原文引文（`paper_id` + 页码 + 逐字引文）
- **数据链**：数据集 → 固定版本 → 查询 → 收据（版本 + SHA-256 + 口径 + 命中行数）

但它们互不相通，于是最常见的科研场景断了：论文里写「处理组比对照组高 12%」，
这个 12% 来自某张表的某次计算，而现在**无法从论文里的那句话回指到那张表的哪一版**。
反过来，数据算出一个数，也无法说明它对应论文里的哪句话。

两条链各自都强调「证据是位置声明，不是真理声明」，但合在一起时还能多问一句：
**两边那个数字，对得上吗？**

本 spec 把两条链接起来：研究记录的结论可以同时引用原文引文与数据收据，
并自动把两边的数字做字面比对。

## 行为

1. **证据有两种**：`kind="paper"` 是原文引文（必须逐字出现在那一页）；`kind="data"` 是
   一条数据查询收据的引用（用 `receipt_id`）。没写 `kind` 的按 `paper` 处理。
2. **收据引用要校验**：收据必须存在且 `status="completed"`，否则拒收。
   关键事实（问题、单位、粒度、分母、行数、数值摘要）抄进记录，让记录能脱离收据文件单独读懂。
3. **自动数字比对**：一条结论同时有原文引文与数据收据时，把引文里的数字与收据摘要里的数字
   做字面比对，给出 `matched` / `mismatch` / `unresolved` / `not_applicable`。
4. **百分比按比例归一**：`12%` 与 `0.12` 指同一个量，比对时算对上，但会注明「比例写法不同」。
   `12%` 与 `12` 指的是不同的量，不算对上。
5. **比对只管字面**：只回答「论文里写的那个数和这张表算出来的一样吗」，
   不判断结论对不对、口径有没有偷换。这句话必须写在结果里。
6. **收据带数值摘要**：查询收据新增 `summary`——按类目聚合时是各组的值，否则是命中行数。
   没有它，论文里的数字就没有可比的对象。
7. **界面**：论文面板的工具栏有数据收据选择器，选中引文与一条收据后一起发给 Agent；
   记录视图分别渲染两种证据，并显示数字比对结果。
8. **Agent 侧**：`Data` 的 `query` 动作可以带类目/度量/聚合；`Research` 的 `save` 动作
   的证据项支持 `kind` 与 `receipt_id`。

## 验收标准

- [ ] AC-1：结论可以引用一条数据查询收据，收据不存在或未跑完时拒收。
- [ ] AC-2：同一条结论既有原文引文又有数据收据时，自动产出数字比对结果。
- [ ] AC-3：只有论文引文的结论不做数字比对。
- [ ] AC-4：百分比与比例写法不同但数值相等时判为对上，并注明写法不同。
- [ ] AC-5：数值对不上时明确报 mismatch，并说明「原文里的数字与这次查询的结果对不上」。
- [ ] AC-6：聚合查询的收据带各组的数值摘要；普通查询带命中行数。
- [ ] AC-7：面板能选一条数据收据与引文一起发送，载荷含收据 id 与关键事实。
- [ ] AC-8：记录视图分别渲染两种证据，并显示数字比对结果与「不是验证」的说明。

## 非目标

- 不做语义级的一致性判断。字面对不上不代表结论错，也可能是口径不同。
- 不自动把论文里的数字与数据算出来的数做换算或单位转换。
- 不做多数据集合并比对。
- 不改 Agent 主循环、工具批次与 Hook 阶段顺序。

## 风险与回滚

- 数字比对是字面的。论文里的 12% 与数据算出的 0.12 会被判为对上（并注明写法不同），
  但如果两者本意不同，这个结论就是错的——所以界面必须同时显示「单位与口径是声明」。
- 抄进记录的收据事实是快照。收据文件后来若被改动，记录里的数字不会跟着变；
  这是刻意的，记录要能自证。
- 回滚：`src/data/numeric.py` 是新增，删掉即回到现状；已有记录里的 `kind="data"` 证据
  需要同时去掉才能读，两处改动要一起做。
