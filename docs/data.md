# 数据工作台

把本机数据文件变成**可回指的数据集**：导入 → 检查 → 查询 → 收据。

它解决的是科研里和「引用原文」同样常见、却更难回答的一条链路：**论文里那个数字是怎么来的。**
「处理组提升 12%」——12% 来自哪张表、哪一版、按什么口径算的？没有收据就说不清。

## 三条硬规则

都是为了不让数据在转述中失真：

1. **类型是声明的，不是推断的。** CSV / TSV 的值一律按文本处理，`001` 就是 `001`，
   不猜类型也不猜单位。要做数值比较或求和，必须先把该列**显式**解释为数字。
2. **转换失败保留原文。** 转不动的值单独计数并保留原样，**绝不变成 0、也绝不变 null**。
3. **四种缺失分开算。** 缺字段（键不存在）、显式 null、空字符串、转换失败是四件不同的事，
   混成「没有数据」就等于把问题藏起来了。

另外：**原文件变了或丢了就用旧数据糊弄是不允许的**——检查直接报错，不给缓存预览。

## 数据集模型

```
数据集 = 逻辑容器 + 若干不可变版本
```

- 导入一个文件 → 生成一个版本。同名文件**各自**成独立数据集；只有显式「加版本」才归到一起。
- 版本是原始文件本身，导入后不改。版本号由位置推导（第一个是 v1）。
- 可用性是三态：`present` / `changed`（大小变了）/ `missing`（文件没了）。
  按大小判断，不重算哈希；哈希只在检查时重算，用来确认「拿到的还是当初那一份」。

存储在数据目录的 `data/` 下：`catalog.json` 是索引（原子写），`files/<版本 id>` 是原件，
`receipts/<查询 id>.json` 是查询收据。

## 检查

检查把一个版本读成表格，给出：

- **字段画像**：观察到的类型、缺字段数、显式 null 数、空字符串数、解释状态、转换失败数。
- **质量汇总**：缺字段 / 显式 null / 空字符串 / 重复行 / 转换失败 / 跳过的空行 / 解析器版本。

「预览数字」是**试算**：只看前几行并给出转不动的样例，不改任何东西；确认后才应用。
应用后该列才能参与数值比较与求和。

在**未解释**的文本列上做 `>=` / `<=` 会直接报错并提示先解释，不返回一个空结果——
悄悄算错比报错更糟。

## 查询与收据

查询支持过滤（`contains` / `eq` / `gte` / `lte` / `missing` / `null` / `empty`）、
排序、分页，以及按类目聚合（`count` / `sum`，最多画 50 组）。

每次查询留下一条**收据**：

| 字段 | 说明 |
| --- | --- |
| `dataset_id` / `asset_id` / `sha256` | 读的是哪个数据集的哪一版 |
| `question` | 这次查询要回答什么 |
| `spec` | 过滤、排序、列选择——口径本身 |
| `unit` / `grain` / `denominator` | 单位、粒度、分母的**声明** |
| `row_count` | 命中行数 |
| `acceptance` | 可信度状态，默认 `needs_review` |

收据可以写进研究记录当作证据，这样论文里的数字就能回指到具体的数据版本与查询口径上。

> 口径是**声明**，不是检验。收据只说明这次查询读的是哪个版本、按什么口径算的，
> 不说明这个数字在科学上意味着什么。

## 图表

图表是**带出处的规格**，不是图片。后端生成一份 JSON，前端照着渲染（PurrCat 不引入图表库，
手写 SVG 渲染器）。规格内容寻址、可被引用，就像查询收据一样。

四种图型：`bar` / `line` / `area` 按类目聚合，`scatter` 逐行画点。
金融专用的蜡烛图、桑基图与科研场景无关，不做。

每份规格都带着这次画图的全部依据：

| 字段 | 说明 |
| --- | --- |
| `chart` | 图型、横轴列、纵轴列、聚合方式 |
| `rows[].value` / `rows[].x` / `rows[].y` | 数据点 |
| `rows[].rowProvenance` | 这个点来自原文件第几行 |
| `source.datasetId` / `assetId` / `sha256` / `versionLabel` | 读的是哪个数据集的哪一版 |
| `source.dataView` | 口径：用了哪些列、聚合方式、哪些列被显式解释为数字 |
| `source.report` | 完整的质量报告 |
| `source.omittedGroups` / `excludedValues` | 跳过了几组、丢了几个值 |
| `source.caveats` | 单位/粒度/分母的声明与省略说明 |
| `acceptance` | 可信度状态，默认 `needs_review` |

几条拒收规则，都是为了不给读者看一根假的柱子：

- **数值必须是有限数**：缺值与非数值不画，计入 `excludedValues`。
- **标签列与数值列必须不同**：相同则拒收，否则图上分不清横轴是什么。
- **数值运算要求已解释**：未解释的文本列不能求和或参与数值比较。
- **重复坐标点拒收**：散点图里重复的点会互相盖住，让用户先决定是聚合还是换轴。
- **最多 50 组**：超出的记入 `omittedGroups`，不静默截断。

规格按自身字节的哈希命名与校验，被改动过就拒绝读取；同样的口径得到同样的 id。

> 方法是**声明**，不是科学检查。画的是描述统计，不是结论。这句话写在每份规格里，也显示在界面上。

## 面板

内置插件 `builtin-data` 入驻中栏面板区：

- 左侧列数据集（带版本数、格式、大小、可用性），右侧是当前版本的检查结果。
- 字段画像表里每列都有「解释为数字」，点一下就重新检查。
- 下方是质量汇总与样本表格（行号 + 源行号）。
- 再下面是画图区：选图型、横纵轴与聚合方式，画出的图带出处。
- 「问 Agent」把数据集视图发给 Agent：能检查的给完整视图，
  **检查不了的就只给身份、来源与校验和，并明确要求不要编造记录**。
